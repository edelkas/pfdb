# Importing

PFDB can import an existing collection from **EMDB** (emdb.eu). Because EMDB
tracks many more fields than PFDB, and because you may only want *some* of them,
import is driven by a **field selection** — chosen individually or through a
[preset](configuration.md).

```
pfdb import --emdb <file> [--preset <name> | --fields <tokens>] [--dry-run]
```

- `--emdb <file>` — path to an `emdb.dat` export.
- `--preset <name>` — a built-in (`all`, `userdata`, `metadata`) or a user preset.
  Defaults to `all`.
- `--fields <tokens>` — a comma-separated field list, overriding `--preset`.
- `--dry-run` — parse and report what *would* happen, writing nothing.

Films are matched by **IMDb id**: importing a film that already exists (same
`imdb-id`) updates only the selected fields on it and leaves the rest untouched;
otherwise a new film is inserted. So imports are repeatable and composable.

## The recommended workflow: user data, then redownload

The most robust way to migrate is to import only *your* data and let PFDB fetch
fresh metadata from the sources:

```sh
pfdb import --emdb emdb.dat --preset userdata   # watch history, ratings, owned, ...
pfdb update --all                                # redownload metadata from IMDb/FA
```

The `userdata` preset keeps the IMDb id (the identity anchor), the title/year (so
the stubs are readable), and your personal fields. `pfdb update` then fills in the
metadata **without touching** your imported user data (see [cli.md](cli.md)).

## Fields and how they map

Field tokens are the same for import and export; see [querying.md](querying.md)
and [configuration.md](configuration.md). The EMDB → PFDB mapping:

| Field token | From EMDB | Notes |
|---|---|---|
| `title` / `original-title` | title group | original ← EMDB "also known as" (approximate) |
| `year` / `runtime` / `synopsis` | year / year / plot | |
| `genres` | genre codes | decoded to names; custom genres resolved |
| `cast` | cast group + actors | with character names |
| `directors` / `writers` / `composers` | year group + people arrays | |
| `topics` | tag indexes + tags | EMDB tags → PFDB topics |
| `groups` | collection id + collections | EMDB collection → PFDB group |
| `imdb-id` | genres group | stored as `tt<id>` source ref (redownload anchor) |
| `imdb-rating` | rating group | value + vote count |
| `user-rating` | rating group | your 0–10 score |
| `watch-date` | genres group | last-played date |
| `watch-count` | year group | play count |
| `owned` / `wishlist` / `favorite` | year group | from the personal bitmask |
| `comments` | comments group | → notes |
| `video-file` | year/rating groups | path, codec, resolution, size |

EMDB fields PFDB has no home for (country, spoken languages, awards, loans,
certification, media/case, …) are ignored. The full `emdb.dat` format is
documented in [import/emdb.md](import/emdb.md).

## Testing note

Parser tests run against a small crafted fixture,
`tests/fixtures/emdb/sample.dat`, regenerated by `tools/make_emdb_fixture.py`. A
full real export can be dropped at `tests/fixtures/emdb.dat` (git-ignored — it is
personal data) to exercise the hidden `[.emdb-big]` smoke test:
`pfdb_tests "[.emdb-big]"`.
